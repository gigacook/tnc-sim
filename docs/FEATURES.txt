LIVE - IN THE BUILD, VERIFIED
==============================================================================
Verified by: node tests/manual.js (all pass), node tests/parity.js (5,511 / 5,511
programs identical to the behaviour record), tests/ui/run.mjs (browser suite),
cargo test. The 2,806-program CAM corpus (2,767 clean on the JS engine) is not
on the current machine and has not been re-run on the Rust engine.

ENGINE (Rust, server/crates/tnc-core):
  - The interpreter, the checks and the material model are one Rust crate:
    native in the server, WebAssembly inside this page (inlined, ~245 KB).
    It replaced the JS interpreter on 2026-10-17 after matching it on every
    program of the behaviour record.

INTERPRETER:
  - Klartext parser/interpreter: L/C/CC/CR/CP/LP/CTP moves, RL/RR as real offset
    paths (not centreline), RND, CHF, CT, APPR/DEP, ZX/YZ plane arcs.
  - Q-parameter formulas FN 0-FN 19, jumps (FN 9, CALL LBL n REP), REP Q.
  - Cycles: 1, 2, 4, 17, 18 (old-style); 7, 8, 9, 10, 11, 19, 32, 247 (non-motion:
    datum shift, mirror, rotation, scaling, tolerance, working plane, datum
    point); 200-215 (drilling/reaming/boring/tapping/slots); 220/221
    (patterns); 230/231 (surface milling); 262-265/267 (thread milling).
  - Touch probe: TCH PROBE blocks parse (both forms). Datum-setting cycles
    408-413, 417 and 419 move and write nominal results. Tool-measuring
    cycles 30-33, 480-483 and 562 are recognized with no motion. Any other
    cycle number reports "TCH PROBE n NOT IMPLEMENTED IN SIMULATOR".
  - M3/M4/M5/M8/M9/M2/M30, M99 blockwise cycle call, correct block-start vs
    block-end M-function timing, tool table via TOOL CALL, TNC-style error
    register.
  - Rigid tapping (17/207/209): spindle direction comes from the sign of
    Q239. Cycle 18 switches its own spindle, no retract.
  - F AUTO approximated as the TOOL CALL block's F (the real control reads a
    cutting-data table the simulator doesn't have - documented simplification).
  - Tools missing from the table are auto-created on program upload/import,
    matching import behaviour on a real control.

TNC 430 / MACHINES (sim/machines.js):
  - A second machine, TNC 430: X Y Z plus an A/B swivel head (B outer, A
    inner). Axis limits, rapids and pivot lengths come from the operator's
    machine-parameter list. Compiled into the engine, so a program compiles
    the same way in the browser and on the server.
  - A tilted tool (A/B, cycle 19) cuts along its real axis in the height
    field; the holder check follows the tool axis.
  - A C rotary table was scoped and dropped by the user; not built.

SIMULATOR / MATERIAL (engine: stock.rs, sim.rs):
  - Height-field material removal: the tool stamps its real radius along
    every feed move, including a tilted tool; scrubbing backwards rebuilds
    the blank; removed volume integrated from the height field. No
    undercuts (height field limitation).
  - Standard vice, on by default: 160 mm jaws on the Y faces, gripping the
    bottom of the blank. Toggle under Effects & view. Crash checks:
    "TOOL INTO THE VICE" / "HOLDER HITS THE VICE". Dimensions are a
    standard guess, not the operator's actual vice.
  - Four operating modes as on the control (PRG EDIT, TEST, SINGLE-BLOCK,
    FULL-RUN), each with its own soft-key row; run comparison (reference A
    vs. current run: cycle time, feed/rapid path, moves, min Z, volume).
  - sim.rs: shared timing/arc tessellation and a safety analysis (rapid into
    material, cutting with spindle stopped, tool below the blank, chip load).

MATERIALS AND LOOK (materials.js, look.js):
  - Alloy presets (aluminium, titanium, steel, stainless, brass, cast iron)
    and industry presets (turbine, aerospace, ground finish, cast): color,
    metalness, roughness, chip/spark color, with a picker.
  - RoomEnvironment via PMREMGenerator for metal reflections, ACES filmic
    tone mapping, FXAA through EffectComposer - all wired through the
    TNC_UI plugin bus's ui.render hook.

THREE.JS: r186, bundled with its addons and the three.quarks particle
library by esbuild (sim/vendor/three-entry.mjs) into one classic script
(window.THREE, window.QUARKS). ColorManagement kept disabled to preserve
the existing r128-style colour look.

PROFILES AND PROGRAM I/O (profile.js, ui.js):
  - One personal profile per browser (IndexedDB via idb-keyval), autosave,
    name prompt on first visit, wipe/reset.
  - Export/import profile as .zip with a Merge/Replace choice on import.
    Per-machine tool table, import/export as TOOL.T.
  - Load .H/.I (UTF-8 or Windows-1252), .zip of programs, drag-and-drop.
    Save as .H with Ctrl+S in numbered TNC listing format (CRLF).
  - PGM MGT program manager, block editor, undo/redo (Ctrl+Z /
    Ctrl+Shift+Z), boot splash, mobile layout.
  - window.TNC_UI plugin bus (scene/tool/tick/crash/resize, ui.render) that
    fx.js, look.js and materials.js attach to.

PROGRAMMING DIALOGS AND UI (dialogs.js, viz.js, i18n.js, ui.js):
  - PRG EDIT mode has one-question-per-step dialogs for CYCL DEF, TOOL DEF,
    TOOL CALL and the path functions, in place of typing raw Klartext only.
  - COORDINATES ? has the 426/430 coordinate keypad (manual inside front
    cover, p. 66-67): axis keys X Y Z IV V, 0-9, decimal point, -/+,
    I incremental, P polar, Q parameter, actual-position capture (the
    simulated DRO position), CE, NO ENT, ENT, END, DEL.
    P gives the polar form: L -> LP, C -> CP, CT -> CTP (6.5), APPR -> APPR
    PLT / PLN / PCT / PLCT and DEP LCT -> DEP PLCT (6.3 p. 134: position data
    Cartesian or polar; examples p. 155-157); CC stays Cartesian (p. 151);
    DEP LT / LN / CT have no position, so no polar form.
    PR / PA questions get the same keypad without axes, and take bare
    (-90, I-90) and whole words (PA-90, IPA+60, PR+25, IPR-5).
    The PC keyboard does the same: axis letters, I, P, + -; x10iy5 typed
    without spaces gives X+10 IY+5.
    NOT VERIFIED against a 426/430 or the programming station (CONTINUE
    OPEN K1), i.e. simulator choices, not manual facts:
      - 430 key mapping IV = B, V = A (machines.js axis order);
      - PC shortcuts # = actual position, DELETE = CE, SHIFT+ENTER = NO ENT,
        ESC = DEL (simulator-only; the control has its own keys);
      - END takes the entry typed on the line before ending the dialog
        (manual p. 67 says only "End the dialog immediately"; the "press
        END to accept" text on p. 68 is about editing words in a stored
        block, not dialog entry);
      - I and -/+ toggle the word being entered; I after a word with its
        value starts the next word;
      - CE pressed twice also drops the axis;
      - ACTUAL POSITION with no axis selected fills X Y Z (CC: X Y);
      - the route to APPR/DEP polar forms through P during the coordinates;
        APPR PLT / PLN have no manual example (they follow from p. 134 only;
        PLCT, PCT and DEP PLCT are the manual's block forms).
  - Tool list opens in the machine view (key T). Keys: 1-4 operating mode,
    5-9 speed, F focus view (hides the right pane).
  - Right pane tabs: Diagnostics, Reference (keys, cycles, tools, machine,
    manual sections), and the operator's own programs (created, edited,
    version; projects collapsed).
  - Position (DRO) is an overlay on the 3D view, not a separate panel.
  - Axis vectors from the program zero to the tool, and click-to-pick with
    coordinates (viz.js).
  - Interface language: English or Swedish, set from the profile dialog.

BEYOND THE SINGLE FILE (server/, web/):
  - server/: a Rust server (axum, SQLite) that checks programs with the same
    Rust engine the page runs - one interpreter for the browser and the server. Accounts, a
    versioned program library, per-machine tool tables, share links, an
    AI proxy to OpenRouter.
  - web/: a React (Vite, TypeScript) app for the server - sign in, edit and
    check programs, browse and restore versions, share by link.
  - desktop/: the Tauri 2 desktop app. Runs the server's own crate in-process
    on 127.0.0.1 (remembered port), SQLite in the platform app-data folder,
    one-time sign-in link for the local operator, Host allow-list + CSP, no
    Tauri IPC for the page, external links to the system browser, single
    instance. Built and launched on Linux; macOS/Windows via CI only.

PHONES AND TABLETS (<= 900 px, sim-shell.html + ui.js):
  - Three workspaces (Program, Graphics, Status) in the page's own scroll;
    tabs (arrow keys, Home/End) or a sideways swipe on the workspace. Swipes
    never start on the 3-D view, sliders, text fields, the soft keys or
    anything that scrolls sideways, and never on a vertical drag; they only
    navigate. Each workspace keeps its scroll position; the canvas and WebGL
    context are never recreated.
  - Soft keys + the block line (PRG EDIT) in a dock at the bottom of every
    workspace, 8 keys at a time with a row switch (the control's own
    soft-key row paging). The dock rides above the software keyboard.
  - Header: modes, program + run state, check count (opens the checks).
    DEV, + New, Lessons, AI, Help, Focus, Profile in a MENU drawer (modal:
    focus inside, page inert, Esc / scrim / swipe right close it).
  - Dialogs: full-height sheets following the visual viewport; the AI and
    new-program actions stay on screen. Inputs 16 px (no iOS zoom; pinch
    zoom stays on), 44 px touch targets, safe areas, long blocks wrap.
  - Accessibility (all widths): modal focus trap + inert background + focus
    return, WAI-ARIA tabs with roving tabindex, shortcuts never take Enter /
    Space from a keyboard-focused control or arrows from a tab list, polite
    announcements for run state and check counts only, main landmark,
    labelled canvas / listing / DRO, check count as text not colour only,
    html lang follows the language. en + sv strings.

AI LOOP (ai.js + part.js):
  - The tool table goes to the model as constraints: type, Ø, reach before
    the holder touches, smallest inside corner, plunge and depth rules, safe
    S/F; plus what the control does not have (FK, SL cycles, 251+, ...).
  - Plan: the model writes a part spec (face, rect/circle/poly pocket, hole,
    slot, engrave, text, outside profile). Expand: text becomes exact
    single-stroke capitals (A-Z, 0-9, Å Ä Ö Ü Č Ć Š Ž Đ), every feature is
    checked against the tools. Write, check, then the program is machined
    on the height field and measured against the spec (match %, not-cut and
    cut-where-it-should-not regions by position, per feature); up to 3
    refinement rounds. Best program wins.
  - Answers cut off at max_tokens are continued; only-thinking answers are
    retried with twice the budget; a dropped connection once. Defaults 32k
    tokens, low reasoning (measured: as accurate as medium, minutes faster);
    server cap 64k. Live bench: 34-74 % match before -> 96-100 % now.
  - The GitHub Pages simulator stays a self-contained single file either
    way; the server and web app are an optional layer around it.

BUILD:
  - build.py is fully data-driven: LIBS (JSZip, idb-keyval), MODULES
    (sim/*.js files, ui.js last), TEXTS (this file, docs/HISTORY.txt,
    docs/RELEASES.txt/ROADMAP.txt when they exist -> window.TNC_* globals
    for this DEV modal). A new module is one line.
